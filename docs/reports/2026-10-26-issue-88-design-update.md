### 💬 Remarks

- 설계 문서: `docs/evaluation-backend-contract-design.md` (draft 0.1)
- 현재 상태는 **설계 초안 작성 완료, 담당자 합의 전**입니다. 이슈 종료·구현 완료 상태가 아닙니다.
- 기존 snapshot·harness·trace·채점기를 재사용하고, service에 비동기 평가 작업과 결과 저장 구조를 추가하는 방향입니다.
- 서버가 저장된 사례별 결과로 합격을 계산합니다. 생산자가 보낸 `valid/results`만으로 합격을 확정하지 않습니다.
- 원인 분석용 실패 실행은 증거로 유지하고, 후보 검증용 평가의 필수 사례·회차·정적 검사 통과 여부를 별도로 확인합니다.
- 평가 중 workspace를 다시 읽지 않고 기준·후보 snapshot과 평가셋·판정 기준을 고정합니다.
- 기존 `run_scenarios`, `save_proposal`, `apply_patch` v1.3은 유지하고 새 평가 도구와 `save_proposal_v2`를 추가하는 안입니다. 현재 서버에 추가된 것은 아닙니다.
- 새 검증 경로와 기존 제안서를 구분하며, 기존 승인 동작의 전환은 담당자·사용자 확인 후 별도로 진행합니다.
- Python 트리거 평가의 파싱·오집계 수정은 해당 담당자와 협의할 별도 구현입니다.
- 주문 Agent 내부의 예산 강제·멱등 조회·실행 중단 지원은 담당자 협의가 필요합니다. 미지원 기능을 지원한다고 가정하지 않습니다.
- 안전성 지표, 미측정·부분 결과, 재시도 비용, 신규 Skill의 arm별 기대 동작도 설계에 포함했습니다.
- 자동 수정·patch 적용·운영 배포는 이번 범위에 포함하지 않았습니다.

### 합의 후 구현 순서

1. 실행 장부 조회와 batch·역할·revision·검사 조건 저장을 보완합니다.
2. 고정 입력의 비동기 평가 작업·결과 저장·예산·보고서를 구현합니다.
3. 새 REST/MCP·제안서 검증을 연결하고 Python 생산자 전환과 격리 서버 검증을 진행합니다.

다른 담당자의 코드는 변경 대상과 계약 영향을 확인받은 뒤 수정합니다.
